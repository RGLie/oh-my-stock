# 개발 기록

## 2026-09-05 · 개발 착수

- 사용자 요청: 설계에 따라 개발 시작, 개발 전 과정 문서화, 토스처럼 깔끔하고 읽기 쉬운 UI, 루트 `.env`의 토스 인증정보 사용.
- 기존 파일: README, 설계 초안, 사용자 `.env`. 기존 애플리케이션이나 Git 저장소는 없었다.
- 인증값은 출력하지 않고 변수명만 확인했다. `.env`를 수정하거나 덮어쓰지 않는다.
- 로컬 CLI 실행을 유지하기 위해 Node.js 서버 + React/TypeScript + SQLite 구조를 채택했다. Cloudflare 배포용 Sites 런타임은 로컬 자식 프로세스를 실행할 수 없어 이번 로컬 앱에 사용하지 않는다.
- Node 24의 내장 SQLite로 네이티브 빌드 의존성을 줄이고, 금액 계산은 Decimal로 수행한다.
- 토스 공식 REST 명세 1.2.14를 `docs/vendor/toss-openapi.json`에 보존했다. 명세에서 REST 시세/잔고/환율 구조와 별도 AsyncAPI WebSocket 명세의 존재를 확인했다.
- 토스 토큰은 클라이언트당 1개만 유효하고 재발급 시 이전 토큰이 무효화됨을 확인했다. 서버에서 토큰 발급을 단일화하고 불필요한 재발급을 피한다.
- 사용자에게 포트폴리오 시작 방식, Claude CLI 설치 상태, 브라우저 검증 여부를 질문했다. 독립적인 UI/서버 개발은 계속한다.

### 디자인 결정

밝은 회색 작업 배경, 흰색 카드, 진한 회색 본문, 파란색 핵심 버튼, 여유 있는 행 간격과 정렬된 숫자. 사이드바와 자산 요약을 첫 화면에 배치한다. 실제 데이터가 없을 때 허구의 자산/수익률을 표시하지 않는다.

### 기록 방식

각 구현 단계의 변경 이유, 검증 명령과 결과, 외부 연결 상태, 남은 제한을 이 문서에 추가한다. 기능 사용법과 설정은 README, 설계 변경은 ARCHITECTURE, 최종 검증은 VALIDATION에 정리한다.

## 2026-09-05~06 · 자동 조사 요구 반영

- 사용자 후속 요청: 자료를 수동으로 고르지 않아도 질문·새로고침만으로 모델이 웹을 조사할 것. 뉴스·실적·매크로·지표·환율 등을 절차별로 나눌 것. 한국어 기본, 보고서 가독성, 모델·effort 선택.
- 기존 자료 고정 분석에 자율 조사 모드를 추가했다. 기본값은 자동 조사다. 수동 원문은 선택 사항으로 이동했다.
- `analysis-skills`에 7개 분야 절차를 분리했다. 앱의 기준 편집기로 수정·저장한 프롬프트는 기본 파일보다 우선 적용한다.
- Codex에는 live 웹 검색, Claude에는 WebSearch/WebFetch를 연결했다. 셸·임의 파일 작업을 허용하지 않으며 토스 비밀값은 자식 프로세스 환경에서 제외한다.
- CLI 스트림에서 검색 이벤트와 실제 모델 정보(제공되는 경우)를 읽어 진행 상태를 저장한다. 최대 실행 시간, 취소, 중복 요청 합치기, 한쪽만 재시도, 재시작 복구를 구현했다.
- 같은 시점의 포트폴리오를 두 모델에 전달하고 조사 결과는 공유하지 않는다. 후속 질문도 각 AI의 이전 결과만 참고한다.
- 보고서를 핵심 판단, 짧은 요약, 주요 수치 카드, 포트폴리오 영향, 접이식 행동·리스크·출처로 개편했다. 나란히 보기와 넓게 읽기를 제공하며 모바일 본문은 16px이다.
- 구조화 JSON과 근거 ID를 검증하고 검색/출처 미확인 결과에는 한계를 표시한다. 형식 검증을 사실 검증이라고 표현하지 않는다.

### 실제 모델 연결 검사

`scripts/check-ai.ts`는 가상 기업의 매출 비교만 사용해 두 CLI 구조화 응답을 확인했다. Codex 약 17초, Claude 약 15초에 성공했다.

`scripts/check-research.ts`는 개인 보유정보 없이 공개 Adobe 실적 질문만 전달했다. Codex는 약 50초/웹 이벤트 3회/출처 2개, Claude는 약 38초/웹 이벤트 2회/출처 2개로 한국어 보고서를 반환했다. Claude가 보고한 실제 모델은 `claude-sonnet-5`였다. Codex는 해당 실행의 실제 모델 ID를 출력하지 않아 기본 모델로 표시했다.

두 결과에 재무 수치의 불일치가 있었다. 웹 검색 성공만으로 수치가 정확하다고 주장하지 않는다. 원문 숫자·단위 보존, 한국어 단위 변환 검산, 원문 수치 병기 지침을 보강하고 수치별 출처와 독립 보고서 비교를 제공했다. 불일치 수치를 실데이터나 검증된 투자 정보로 DB에 이식하지 않았다.

### 뉴스 검색과 승인 검토

개발 중 보유 티커를 Google News에 보내는 요청은 자동 승인 검토가 개인정보 전송 동의 부족으로 거부했다. 사용자에게 전송 범위와 대상을 설명하는 질문을 보냈으며, 해당 승인을 받았다고 간주하지 않았다. 일반 공개 시장 키워드로만 연결을 검증했다.

RSS 검색의 보유 티커 사용을 기본 비활성 옵션으로 변경했다. 앱 사용자가 체크박스를 직접 선택할 때만 보유 티커를 검색어에 넣는다. 자동 AI 조사 기능은 사용자가 요청한 모델의 웹 검색 도구를 사용한다.

한국어 RSS 파라미터와 기본 검색어로 변경한 후 공개 키워드 `미국 연준 금리`를 검사해 24개 중 24개 한국어 제목을 확인했다. 제목·링크만 저장하는 자료는 원문 확보로 표시하지 않는다.

- 지연된 REST 시세 응답이 사용자가 방금 수정한 수량·투자 근거를 덮어쓰지 않도록 최신 저장 레코드에 시세만 반영한다.

- 서버가 켜져 있는 동안 15분 간격으로 관측 평가액 스냅샷을 추가한다. 과거 성과를 생성하지 않는다.
- 별도 메모리 DB 검증 서버에서 모델/effort 선택, 자료 없는 새로고침, 기준 편집, 소수점 종목 추가·수정, 자료 저장, 투자 기록, 현금·원칙 저장, 배분 계산을 브라우저로 확인했다.

- Windows 5 PowerShell에서 초기 Node 선택 검사가 실패했다. 호환 Node의 버전 문자열을 직접 확인하고 번들 런타임을 우선하도록 수정했다. 상태 확인, 빌드, 테스트, 시작 명령을 검증했다.
- `Start-OMS.cmd`, `Login-Codex.cmd`, `Login-Claude.cmd`, 공통 `scripts/oms.ps1`을 추가했다. 사용자 `.env`나 시스템 PATH를 변경하지 않았다.

### 의존성 점검

초기 취약점 검사 결과에 따라 Vite 7.3.5, fast-xml-parser 5.11.1로 갱신했다. 이후 전체 감사에서 발견된 Windows 개발 서버의 낮은 등급 esbuild 취약점도 0.28.1 override로 갱신했다. 최종 `pnpm audit` 결과는 알려진 취약점 0건이다. esbuild와 공식 Claude 설치 스크립트만 allowBuilds에 허용했다.

### 최종 연결 확인

최신 서버를 `http://127.0.0.1:4310`에서 프로덕션 모드로 재시작했다. 실제 토스 동기화는 보유 종목 9개, 시세 기준 시각 9개, 환산 계산 complete, WebSocket 구독 live를 반환했다. 두 CLI 로그인을 확인했고 기존 분석 기록 1개가 유지됐다. 장중 체결 수신 자체는 이번 주말 검증에서 확인하지 않았다.

검증 명령·통과 범위·남은 제한은 [VALIDATION.md](VALIDATION.md)에 정리한다. 기존 [BLUEPRINT.md](BLUEPRINT.md)는 초기 논의 기록으로 보존하고 실제 구조는 [ARCHITECTURE.md](ARCHITECTURE.md)를 기준으로 한다.

## 2026-09-06 · 실행 가시성·상세 히스토리·투자 프로필·데일리 브리프

### 요청과 설계

사용자가 멈춘 것처럼 보이는 분석 대기 화면, 입력 프롬프트·최종 답변의 상세 기록, 공통/분야별 프롬프트 열람, 투자 성향·목표 반영, 오늘의 시장·실적 일정 브리핑을 요청했다. 기존 로컬 개인용 구조와 한국어 보고서를 유지하며 네 기능을 연결했다.

진행 상태는 임의의 완료율 대신 경과 시간과 실제 실행 이벤트를 사용한다. 과거 프롬프트는 현재 템플릿을 이용해 재생성하지 않고 실제 실행 입력을 고정 저장한다. 투자 성향과 목표는 임의로 정하지 않는다. 데일리 브리프는 한국시간 날짜와 미국 거래일을 구분하며 새로고침으로 시작한다.

### 서버 구현

- 투자 프로필 저장 API와 기본 미입력 값, 금액·하락률·유효 날짜 검증을 추가했다. 기존 투자 원칙과 함께 분석 입력 및 중복 판단에 포함한다.
- 실행 직전에 공급자별 trace를 만들고 실제 CLI 입력, 템플릿/공통 지침, 당시 투자 정보, 출력 스키마를 저장한다. 최종 응답, 오류, 전달·완료 시각, 제한된 활동 타임라인을 보존한다.
- 과거 버전의 trace 없는 기록은 원래 보고서만 제공한다. 실패 답변의 원문도 남기고 재시작으로 중단된 trace를 마감한다. 일반 상태 조회에는 원문 trace를 포함하지 않는다.
- 기록 검색·종류/상태 필터·페이지 조회·모델별 상세·JSON 내보내기, 현재 프롬프트 라이브러리 API를 추가했다.
- CLI 출력 이벤트에서 웹 조사와 작성 단계를 추출하고 검색 ID로 횟수 중복을 제거했다. 5초 로컬 실행 확인과 실제 출력 수신을 구분한다. UTF-8 스트림 디코딩으로 문자 경계에서 한글이 깨지지 않게 했다.
- `analysis-skills/daily.md`, 한국시간 요청 범위, 지수·일정·우선 확인 항목의 구조화 응답을 추가했다. 날짜 불일치와 지수/일정 출처 누락을 검사한다. 출력 스키마 캐시를 내용 해시 파일명으로 바꿨다.

### 화면 구현과 발견한 문제

- AI 파트너의 질문·분석/데일리 브리프 탭, 화면 상단 실행 상태, 모델별 보고서, 지수·일정 카드와 출처를 추가했다.
- 사이드바에 AI 실행 기록을 추가했다. 실제 전송문, 공통/분야별 지침, 당시 설정·자료, 최종 답변, 타임라인을 펼쳐 볼 수 있다. 프롬프트 라이브러리에서 다음 실행의 기준을 편집한다.
- 설정에 투자 성향·경험·목표 금액/시점·감내 하락률·자금 필요·제외 조건을 추가했다.
- 브라우저 검사에서 `prefers-reduced-motion: reduce`를 확인했다. 기존 로딩 애니메이션 정지 원인에 해당한다. 운영체제 설정을 변경하지 않고 경과 시간·최근 실행 확인 텍스트를 1초 단위로 갱신했다. 모바일에서 0초→7초→42초 변화와 검색 상태를 직접 확인했다.
- 긴 브리핑 질문이 보고서 제목을 밀어내는 문제를 수정했다. 날짜가 포함된 짧은 작업 제목과 선택 상자의 최대 너비를 적용했다.
- 실제 보유 DB와 분리된 메모리 서버에서 기준 편집, 투자 성향 저장 후 화면 재진입, 진행 중 히스토리 열람, 브리핑 완료/일정 표시, 답변 원문, 취소 기록을 확인했다. 390px 모바일에서 가로 넘침 없이 375px 콘텐츠 폭을 유지했다.

### 실제 AI 및 자동 검증

`scripts/check-daily.ts`는 `.env`나 사용자 포트폴리오를 읽지 않고 공개 시장 자료만 요청한다. 실제 Codex는 웹 검색 3회·출처 4개·81초, Claude는 검색/페이지 확인 6회·출처 2개·75초로 한국어 브리핑을 반환했다. 두 실행 모두 입력 전달, 최종 답변 콜백, 진행 갱신, 요청 날짜 일치를 확인했다. 검색 요청 횟수 제한 문구는 모델에 대한 지침이므로 실제 횟수를 강제로 제한하지 않는다. 이 검사는 투자 수치의 사실 정확도를 보장하지 않는다.

자동 테스트 26개가 통과했다. 새 검증은 실제 전송문과 저장문 일치, 프로필·기준 변경 후 과거 기록 보존, 필터·내보내기, 한국시간 자정, 브리핑 날짜/출처 오류, 내부 사고·원시 도구 입력 제외를 포함한다. TypeScript와 프로덕션 빌드도 통과했다. 의존성 추가는 없다.

### 최종 반영

진행 중인 분석이 없음을 확인하고 4310 프로덕션 서버를 최종 코드로 재시작했다. API에서 기존 보유 9개·분석 기록 2개 보존, 투자 프로필 제공, 8개 템플릿과 daily 기준, 두 CLI 인증 상태를 확인했다. 메모리 QA 서버는 종료했다.

마지막 실제 OMS 브라우저 화면 열기 요청은 자동 승인 검토의 사용량 한도 오류로 차단됐다. 이를 우회하지 않았다. 앞서 완료한 격리 브라우저 검증과 구분하며, 최종 재시작 후의 화면 재열기는 완료했다고 주장하지 않는다. 서버 API 상태 확인과 문서 마무리는 완료했다.

## 2026-09-07 · 가독성 개선·GitHub 저장·PC 없는 개인 접속 준비

### 요청과 결정

사용자는 정보량을 유지한 가독성 개선과 `RGLie/oh-my-stock`으로 커밋·푸시를 요청했다. 외부 휴대폰 접속은 개인 VPN을 선택했고, PC를 꺼도 새 질문·새로고침이 필요하다고 명확히 했다. 서버 조건은 새 서버·월 1만 원 이내다. 실제 비용·사양을 먼저 제시하고 결제·개설을 확인받기로 했다.

### 읽기 화면

보고서 본문을 17px로 맞추고 핵심 판단, 수치, 포트폴리오 영향, 근거의 간격과 대비를 조정했다. `ReportText`는 원본 문자열을 저장 단계에서 바꾸지 않고 표시할 때만 긴 문단을 문장 경계에서 나눈다. 브리프의 시장 설명·일정 영향에도 적용했다. 모바일 수치 카드는 한 열, 중간 폭의 모델 비교도 한 열로 전환해 내용의 너비를 확보한다. 실행 기록의 원문과 보조 설명도 읽기 크기를 조정했다.

격리 브라우저 서버에서 공개 실적 보고서의 데스크톱·모바일 화면을 확인했다. 390px 화면에서 문서와 스크롤 폭 375px가 같았고, 본문 17px/줄 높이 32.3px를 확인했다. QA 서버는 이전 공개 조사 결과 파일이 없어도 자체 가상 보고서로 시작하도록 수정했다.

### 원격 실행 준비

기존 Node·SQLite와 두 공식 CLI를 Linux VPS로 옮기는 방향을 정했다. Tailscale Serve의 검증된 신원 헤더로 본인 계정만 허용하며 기존 loopback 바인딩, Host·Origin·변경 토큰 검사를 유지한다. 원격 설정 일부만 입력하면 시작을 거부하고, 원격 모드의 인증 없는 localhost 우회도 허용하지 않는다.

Linux systemd 템플릿과 배포·이전·복구 문서를 추가했다. CLI 캐시는 OS 홈 또는 `CODEX_HOME`에서 읽고, POSIX 실행 취소는 개별 프로세스 그룹을 종료하도록 준비했다. 실제 Linux sandbox·CLI 로그인·메모리·취소·재부팅과 토스 API 접근은 배포 후 확인해야 한다. PC에서 Tailscale을 설치하거나 `.env`의 키를 변경하지 않았다.

공식 상품 페이지에서 netcup 2 vCore/4GB/80GB, IPv4 포함 월 €4.88, 설치비 €0를 확인했다. 6개월 약정·6개월 청구이므로 월 비용뿐 아니라 초기 €29.28도 명시했다. ECB 환율과 가정한 카드 수수료로 월 약 8천 원·6개월 약 4만 7천 원을 참고치로 계산했다. 결제 국가의 실제 세금과 청구액은 가입 후 확인해야 한다. 상세 출처는 클라우드 문서에 남겼다. 서버는 아직 개설하지 않았다.
